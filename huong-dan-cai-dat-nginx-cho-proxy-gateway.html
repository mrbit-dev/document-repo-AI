Hướng dẫn cài đặt Nginx làm Proxy Gateway cho VPS Ubuntu

Trỏ domain, cài Nginx Reverse Proxy về ứng dụng nội bộ (127.0.0.1:PORT), và cấp SSL miễn phí Let's Encrypt.

⚙ Kiến trúc tổng quan

Dùng Nginx làm Reverse Proxy để "mở khóa" ứng dụng đang chạy bên trong VPS ra Internet thông qua tên miền + HTTPS. Người dùng chỉ cần nhớ domain, không cần nhớ IP hay port.

🌐 Internet

│  agent.example.com
│  Port 80 / 443 (HTTPS)
▼
🖥️ Nginx (Reverse Proxy + SSL)

│  proxy_pass → http://127.0.0.1:20128
▼
🚀 Ứng dụng nội bộ (OmniRoute)

│  Lắng nghe trên 127.0.0.1:20128
▼
📦 Port 20128 (chỉ truy cập từ bên trong VPS)
Lưu ý an toàn: Nếu ứng dụng của bạn đang lắng nghe trên 0.0.0.0:20128 (mọi interface), hãy đổi về 127.0.0.1:20128 (chỉ local) để không lộ port ra ngoài. Nginx sẽ là "cánh cổng" duy nhất.

0 Chuẩn bị

  • VPS đã cài hệ điều hành Ubuntu 20.04 / 22.04 / 24.04 và có IP công khai.
  • Một domain (ví dụ devkit.vn) mà bạn kiểm soát được phần DNS.
  • Ứng dụng của bạn đang chạy trên VPS, lắng nghe tại 127.0.0.1:20128.
  • Truy cập SSH vào VPS bằng user có quyền sudo.
Mẹo: Nên chạy các lệnh với sudo ngay từ đầu để tránh bị lỗi "Permission denied".

1 Trỏ domain về VPS

Vào nơi quản lý DNS của domain (nhà đăng ký tên miền hoặc panel DNS đang dùng), tạo bản ghi A record:

TypeNameValueGhi chú
Aagent203.0.113.151IP công khai của VPS bạn

Ví dụ: bản ghi này sẽ tạo ra hostname agent.example.com trỏ tới IP của VPS.

Chú ý: Đợi khoảng vài phút đến vài giờ để DNS cập nhật. Kiểm tra nhanh bằng lệnh:
Kiểm tra DNS
ping agent.example.com

Nếu kết quả trả về đúng IP 203.0.113.151 là DNS đã hoạt động.

2 Cài đặt Nginx

Cập nhật package và cài Nginx:

Cài Nginx
sudo apt update
sudo apt install nginx -y

Kiểm tra trạng thái Nginx:

Kiểm tra trạng thái
sudo systemctl status nginx

Nếu mới cài, Nginx tự động chạy. Truy cập http://IP_VPS trên trình duyệt sẽ thấy trang chào mừng mặc định của Nginx.

3 Tạo Virtual Host (server block)

Tạo file cấu hình cho domain:

Tạo file cấu hình site
sudo nano /etc/nginx/sites-available/agent.example.com

Dán nội dung sau vào file:

agent.example.com
# /etc/nginx/sites-available/agent.example.com
server {
    listen 80;
    server_name agent.example.com;

    location / {
        proxy_pass http://127.0.0.1:20128;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
    }
}
Giải thích các dòng quan trọng:
  • proxy_pass http://127.0.0.1:20128; — chuyển toàn bộ request đến ứng dụng của bạn.
  • Upgrade + Connection "upgrade" — hỗ trợ WebSocket (cần thiết nếu ứng dụng dùng chat/realtime).
  • X-Forwarded-Proto $scheme — giúp ứng dụng biết người dùng đang truy cập qua HTTP hay HTTPS.

Lưu file: trong nano, nhấn Ctrl+O → Enter để lưu, rồi Ctrl+X để thoát.

4 Enable site và kiểm tra cấu hình

Tạo liên kết (symlink) từ sites-available sang sites-enabled để kích hoạt site:

Enable site
sudo ln -s /etc/nginx/sites-available/agent.example.com /etc/nginx/sites-enabled/
# Vô hiệu hóa site mặc định (trang chào mừng):
sudo rm -f /etc/nginx/sites-enabled/default

Kiểm tra cú pháp cấu hình:

Test cấu hình
sudo nginx -t

Nếu kết quả báo:

Kết quả mong muốn
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful

thì reload Nginx để áp dụng thay đổi:

Reload Nginx
sudo systemctl reload nginx

Truy cập http://agent.example.com — nếu thấy ứng dụng của bạn là thành công! 🎉

5 Mở Firewall

Nếu VPS đang bật UFW (Uncomplicated Firewall), cần cho phép lưu lượng web đi qua:

Mở firewall cho Nginx
sudo ufw allow 'Nginx Full'

'Nginx Full' sẽ mở cả port 80 (HTTP) và 443 (HTTPS). Kiểm tra trạng thái:

Kiểm tra firewall
sudo ufw status
Quan trọng: Nếu ứng dụng của bạn chạy trên 127.0.0.1:20128 (chỉ local), không cần mở port 20128 trong firewall — Nginx sẽ truy cập qua localhost. Đây là cách an toàn nhất.

Nếu không dùng UFW, hãy đảm bảo bảo mật của nhà cung cấp VPS (Security Group) đã cho phép port 80/443 từ Internet.

6 Cài SSL miễn phí với Let's Encrypt

Cài Certbot và plugin Nginx:

Cài Certbot
sudo apt install certbot python3-certbot-nginx -y

Chạy lệnh cấp SSL tự động (Certbot sẽ tự sửa cấu hình Nginx):

Cấp SSL cho domain
sudo certbot --nginx -d agent.example.com

Khi được hỏi về redirect HTTP → HTTPS, chọn:

Lựa chọn redirect
Please choose whether or not to redirect HTTP traffic to HTTPS:
1: No redirect
2: Redirect - Make all requests redirect to secure HTTPS access. <= CHỌN SỐ NÀY

Nhập 2 và Enter. Certbot sẽ tự động:

  • Cấp chứng chỉ SSL, cấu hình HTTPS trên domain.
  • Thiết lập tự động redirect từ http:// sang https://.

Thành công rồi! Bây giờ bạn có thể truy cập an toàn bằng HTTPS:

✔ HTTPS hoạt động
Trước đây: http://203.0.113.151:20128 (lộ IP + port, không bảo mật)
Bây giờ: https://agent.example.com ✅ (đẹp, bảo mật, có ổ khóa SSL)

7 Tự động gia hạn SSL

Chứng chỉ Let's Encrypt chỉ có hiệu lực 90 ngày. Certbot cài sẵn một timer tự động gia hạn. Kiểm tra timer đang hoạt động:

Kiểm tra timer gia hạn
sudo systemctl list-timers | grep certbot

Thử gia hạn giả lập để chắc chắn mọi thứ hoạt động:

Gia hạn thử
sudo certbot renew --dry-run

Nếu không thấy lỗi, hệ thống sẽ tự động gia hạn trước khi hết hạn. Không cần làm gì thêm.

❌ Truy cập http://agent.example.com bị trang chào mừng Nginx (Welcome to nginx)

Site mặc định chưa được tắt. Chạy:

Fix
sudo rm -f /etc/nginx/sites-enabled/default
sudo systemctl reload nginx

❌ Lỗi 502 Bad Gateway

Nginx không kết nối được ứng dụng. Kiểm tra:

  • Ứng dụng đã chạy chưa? Kiểm tra: sudo ss -tlnp | grep 20128
  • Ứng dụng lắng nghe đúng 127.0.0.1:20128 chưa (không phải port khác)?
  • Địa chỉ trong proxy_pass khớp với port thực tế của ứng dụng chưa?

❌ Lỗi 404 Not Found

Thường do proxy_pass sai đường dẫn, hoặc Nginx đang trỏ tới thư mục mặc định thay vì proxy. Kiểm tra lại nội dung file cấu hình.

❌ WebSocket không hoạt động

Đảm bảo file cấu hình có đủ 2 dòng header Upgrade/Connection như ở Bước 3.

❌ Certbot báo lỗi "Domain not found" / "Unable to verify"

DNS chưa trỏ đúng IP hoặc port 80 chưa được mở. Kiểm tra lại Bước 1 và Bước 5.

❌ "Cannot connect to the Docker daemon" / ứng dụng dùng Docker

Nếu OmniRoute (hoặc ứng dụng của bạn) chạy trong Docker, xem cấu hình đã publish port ra 127.0.0.1:20128 chưa, ví dụ: -p 127.0.0.1:20128:20128. Lúc đó Nginx vẫn proxy tới http://127.0.0.1:20128 như bình thường.
