1. DeepSeek Harness là gì?

DeepSeek Harness không phải là một AI model mới. Nó là một framework/runtime để xây dựng và vận hành AI Agent.

Cách hiểu đơn giản nhất:

Agent = Model + Harness

Model
  ↓
suy luận / quyết định
  ↓
Harness
  ├─ Tools
  ├─ Filesystem
  ├─ Shell / Terminal
  ├─ Session
  ├─ Permission
  ├─ Sandbox
  ├─ Sub-agent
  ├─ Workflow
  └─ các plugin khác
  ↓
Thực hiện công việc trong môi trường thật
Điểm quan trọng: Harness biến model từ một hệ thống chủ yếu trả lời bằng text thành một Agent có khả năng quan sát môi trường, gọi tool, thực hiện hành động, kiểm tra kết quả và tiếp tục vòng làm việc.

So sánh chatbot và Agent

ChatbotAgent có Harness
User → Model → TextUser → Agent → Model → Tool → Result → Model → ...
Chủ yếu đưa hướng dẫn/codeCó thể đọc file, sửa file, chạy command, kiểm tra kết quả
Không nhất thiết có state lâu dàiCó session/log/persistence

Tư tưởng kiến trúc

DeepSeek Harness nhấn mạnh kiến trúc plugin: các capability được ghép vào runtime thay vì biến mọi thứ thành một khối core cố định.

2. Cài đặt

2.1 Cách nhanh nhất

npx @deepseek-ai/dsh web

Sau khi chạy, Web UI mặc định có thể được mở tại:

http://127.0.0.1:3080

2.2 Chạy từ source

git clone https://github.com/deepseek-ai/deepseek-harness.git
cd deepseek-harness
pnpm install
pnpm run build
pnpm dsh web
Lưu ý: Repository đang ở trạng thái Developer Preview. Không nên giả định API/plugin/config sẽ giữ nguyên giữa các phiên bản.

2.3 Windows và Ubuntu

WindowsCó thể chạy qua PowerShell/Terminal. Khi làm project thực tế nên chọn một workspace riêng, ví dụ D:\DEVKIT\PROJECT.
UbuntuChạy trong Terminal. Với server, nên cân nhắc reverse proxy, firewall, authentication và không expose Web UI trực tiếp ra Internet nếu chưa bảo vệ.

3. Chạy lần đầu

  1. Khởi động Web UI.
  2. Mở địa chỉ localhost được in ra terminal.
  3. Cấu hình model/provider và credential.
  4. Chọn workspace.
  5. Tạo session.
  6. Giao một task nhỏ để kiểm tra.

Prompt test nên dùng

Summarize this repository and identify its main packages.

Sau đó thử từng bước:

List the files in this project.

Read package.json.

Find the main entry point.

Run the project's tests.

If a test fails, explain the failure first.
Nên bắt đầu bằng task không phá hoại. Đừng ngay lập tức cấp quyền rộng rồi yêu cầu Agent “sửa toàn bộ project”.

5. Agent Loop — trái tim của Agent

Đây là phần quan trọng nhất cần hiểu nếu muốn xây Agent.

User task
   ↓
Agent
   ↓
LLM
   ↓
Model quyết định:
"Đã đủ thông tin chưa?"
   │
   ├── Có → trả lời / hoàn thành
   │
   └── Chưa
        ↓
      Tool call
        ↓
      Tool execution
        ↓
      Tool result
        ↓
       LLM
        ↓
      Tool call?
       ↙    ↘
     Yes     No
      │       │
      └──→────┘
          ↓
        Done

Ví dụ sửa bug

User:
"Fix the failing tests in this repository."

Agent:
1. Inspect project
2. Read package.json
3. Find test command
4. Run tests
5. Inspect failure
6. Read relevant files
7. Edit code
8. Run tests again
9. If still failing → diagnose and repeat
10. Report result

Đây là lý do Agent có thể hoàn thành công việc nhiều bước thay vì chỉ sinh một đoạn code.

6. Tools — tay chân của Agent

Model tự nó không thể “đi vào” filesystem hay terminal. Harness cung cấp tool để model gọi.

LLM
 │
 ├── read_file
 ├── write_file
 ├── search
 ├── bash
 ├── terminal
 ├── web
 ├── LSP
 └── các custom tools

Tool call concept

Model:
"I need to inspect package.json"
        ↓
Tool call:
read_file("package.json")
        ↓
Harness executes
        ↓
Tool result
        ↓
Model continues

Custom tool

Về mặt ý tưởng, anh có thể tạo một tool riêng như:

check_vps()

Tool có thể gọi hệ thống quản trị/VPS rồi trả kết quả về Agent. Ví dụ:

Agent
  ↓
check_vps
  ↓
SSH / API
  ↓
VPS
  ↓
status
  ↓
Agent

7. Session và Persistence

Session không chỉ là một đoạn chat. DSH sử dụng session/event log để ghi lại diễn tiến của Agent.

Session
├── user/message
├── turn/start
├── assistant/chunk
├── tool/call
├── tool/result
├── assistant/chunk
├── tool/call
├── tool/result
└── turn/end

Kiểu thiết kế này giúp theo dõi trajectory, resume/replay và dựng lại lịch sử gửi cho model.

Tại sao quan trọng?

  • Biết Agent đã làm gì.
  • Biết tool nào đã được gọi.
  • Debug hành vi Agent.
  • Resume một công việc.
  • Phân tích trajectory để cải thiện Agent.

8. Permission, Approval và Sandbox

Agent có quyền shell/file thì có thể gây tác động thật. Vì vậy đây là nhóm subsystem không nên bỏ qua.

Khái niệmÝ nghĩa
SandboxGiới hạn môi trường Agent có thể truy cập/thao tác.
PermissionXác định Agent được làm gì.
ApprovalYêu cầu người dùng xác nhận trước một số hành động.

Nguyên tắc an toàn

Development:
Workspace-limited + approval

Testing:
Sandbox phù hợp + quyền vừa đủ

Production:
Least privilege
+ authentication
+ network restrictions
+ logging
+ backup
Không nên: cấp full access cho Agent rồi chạy các prompt không kiểm soát trên máy/VPS chứa dữ liệu quan trọng.

9. Các mode

ModeMục đích
StandardRuntime/toolset đầy đủ cho sử dụng Agent thông thường.
CodeThiên về việc model điều phối nhiều vòng tool/code execution.
MinimalMôi trường tối thiểu, phù hợp thử nghiệm/benchmark.

Các tên/mô tả mode có thể thay đổi theo phiên bản; hãy kiểm tra tài liệu/repository tương ứng với phiên bản đang dùng.

10. Plugin — phần quan trọng nhất để mở rộng

Tư tưởng của DSH là Everything is a Plugin. Thay vì sửa core cho từng nhu cầu, capability có thể được đóng gói thành plugin.

DeepSeek Harness
      │
      └── Plugin
          ├── Tool
          ├── LLM Provider
          ├── Filesystem
          ├── Permission
          ├── UI
          ├── Jobs
          ├── Events
          └── Agent capability

Lifecycle concept

PENDING
  ↓
LOADING
  ↓
ACTIVE
  ↓
UNLOADING
  ↓
DISPOSED

Nếu lỗi:
LOADING → FAILED

Plugin đầu tiên nên làm gì?

Nên bắt đầu bằng một plugin nhỏ, ví dụ đăng ký một tool hello hoặc project_info. Sau khi hiểu lifecycle mới chuyển sang custom LLM/provider hoặc plugin có side effects.

11. Cordis

Cordis là framework/runtime plugin bên dưới kiến trúc Harness. Ba khái niệm cần nhớ:

Context

Nơi các service/capability được cung cấp và truy cập.

Plugin

Đơn vị mở rộng đăng ký capability vào runtime.

Dependency

Plugin có thể yêu cầu service/plugin khác trước khi hoạt động.

Mô hình tư duy

Context
 ├── LLM service
 ├── Tools service
 ├── Session service
 ├── Shell service
 ├── Filesystem service
 └── các service khác

Plugin A → dùng Tools
Plugin B → dùng LLM
Plugin C → dùng Session + Tools

Nếu anh muốn đọc source sâu, nên học Cordis sau khi đã hiểu Agent Loop, Tool và Session.

Điểm mạnh của kiến trúc này là tách Agent logic khỏi model routing. Khi provider thay đổi, Agent layer không nhất thiết phải thay đổi theo.

16. Checklist trước khi đưa vào sử dụng thật

  • □ Khóa phiên bản DSH/package thay vì luôn dùng latest.
  • □ Không cấp quyền filesystem rộng hơn cần thiết.
  • □ Hạn chế shell/network access.
  • □ Bật approval cho thao tác nguy hiểm.
  • □ Có Git/backup trước khi cho Agent sửa project.
  • □ Log tool calls và session.
  • □ Không để API key trong source code.
  • □ Với VPS: không expose UI/API trực tiếp nếu chưa có authentication/reverse proxy/firewall.
  • □ Test plugin ở môi trường riêng trước khi đưa vào production.
