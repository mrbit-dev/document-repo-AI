1. OpenMausBot là gì?

OpenMausBot (còn gọi là MausBot, trước đây là OpenGrokBot) là dự án mã nguồn mở xây dựng một giao diện kiểu ứng dụng nhắn tin để tổ chức nhiều AI Agent. Dự án lấy cảm hứng từ Grok Bot nhưng là sản phẩm độc lập, không liên kết với xAI, Meta, OpenAI hay Manus.

Thay vì chỉ có một chatbot, anh tạo nhiều bot như “Developer”, “Researcher”, “Marketing”, “SEO” hoặc “Assistant”. Mỗi bot có thể dùng model, chỉ dẫn, kênh làm việc, ứng dụng kết nối và môi trường máy tính khác nhau.

Điểm quan trọng: OpenMausBot chủ yếu là lớp giao diện + điều phối (orchestration/harness). Nó không tự cung cấp miễn phí Claude/GPT hay thay thế tài khoản model. Anh cần agent CLI hoặc engine tương thích và quyền truy cập model tương ứng.

Trang dự án: GitHub OpenMausBot · Website chính thức.

2. Công dụng và tính năng chính

Multi-agent

Nhiều bot chuyên môn

Tạo bot theo vai trò, mỗi bot có personality, hướng dẫn, model và lịch sử hội thoại riêng.

Model routing

Chọn model theo bot

Chọn Claude / Codex / Grok theo engine được cấu hình; có thể đổi model giữa cuộc trò chuyện.

Computer use

Agent có máy tính để thao tác

Dùng cloud Linux desktop, Local VM cô lập hoặc máy host khi nền tảng hỗ trợ. Có thể xem màn hình và tiếp quản desktop.

Approvals

Duyệt hành động trước khi chạy

Lệnh shell, chỉnh sửa file và yêu cầu nhạy cảm có thẻ Allow / Deny / trả lời trong chat.

Integrations

Kết nối ứng dụng

Composio kết nối Gmail, Slack, GitHub, Notion, Linear và nhiều ứng dụng khác qua OAuth.

Channels

Phân chia ngữ cảnh

Tạo kênh Work, Personal, từng dự án; mỗi kênh có transcript, chỉ dẫn, working folder và danh sách bot riêng.

Automation

Lịch chạy và webhook

Bot có thể tạo routine theo lịch, webhook hoặc sự kiện từ ứng dụng đã kết nối. Máy phải online để nhận/xử lý các tác vụ local.

MCP / CLI

Điều khiển từ công cụ khác

Có MCP server để client như Claude Desktop / Cursor quản lý bot, kênh và tác vụ trong phạm vi API được giới hạn; có CLI cho script/CI.

Voice

Đọc và nói câu trả lời

Hỗ trợ một số nhà cung cấp giọng nói như ElevenLabs, Fish Audio, Grok và Chatterbox local; tùy nền tảng và cấu hình.

Team templates

Nhập đội bot từ Markdown

Import bộ bot / playbook theo cấu trúc Markdown; kết nối và routine vẫn cần người dùng duyệt/bật.

3. Kiến trúc hoạt động

Ở chế độ desktop, có hai phần chính: ứng dụng giao diện và harness server. Giao diện gửi lệnh HTTP; server quản lý tiến trình agent, nhận sự kiện và đẩy luồng cập nhật về giao diện qua SSE.

Người dùng
   │ chat / yêu cầu công việc
   ▼
OpenMausBot Desktop (React + Electron)
   │ HTTP commands       ▲ SSE events
   ▼                     │
Harness Server (127.0.0.1:8799)
   ├── Driver registry / event bus
   ├── Permission broker (Allow / Deny)
   ├── Claude CLI
   ├── Codex CLI
   ├── Grok CLI
   ├── Boat cloud computer (tuỳ chọn)
   └── Composio connected apps (tuỳ chọn)

Trạng thái, transcript và cấu hình local mặc định nằm trong thư mục ~/.openmausbot. Trên Windows, thư mục home tương ứng là thư mục người dùng; không nên tự ý xóa thư mục dữ liệu này khi gỡ app.

Phân biệt hai cách triển khai: Desktop app phù hợp khi muốn bot chạy CLI trên chính máy đang dùng. Self-host server phù hợp khi muốn chạy harness trên máy chủ rồi kết nối desktop / điện thoại từ xa. Đây không phải cùng một kiểu cài đặt.

5. Cài trên Windows — cách dễ nhất

Khuyến nghị: Với máy Windows của anh, nên bắt đầu bằng bản installer chính thức, không cần clone source hay cài pnpm để dùng app.
1
Tải installer

Mở trang GitHub Releases – Latest và tải file OpenMausBot-setup.exe cho Windows x64.

2
Cài đặt

Chạy file setup. Installer hiện được mô tả là per-user, không cần admin. Nếu Windows SmartScreen báo Unknown publisher, chỉ tiếp tục khi anh đã tải đúng từ trang Releases chính thức: More info → Run anyway.

3
Kiểm tra agent CLI hiện có

Mở PowerShell và chạy:

node -v
claude --version
codex --version

Không nhất thiết phải có cả Claude lẫn Codex. Cài ít nhất một CLI và đăng nhập thành công. Nếu lệnh CLI chưa được nhận diện, xử lý PATH / cài CLI trước.

4
Mở OpenMausBot và tạo bot

Hoàn thành onboarding, chọn engine / model khả dụng. Tạo bot thử nghiệm, gửi yêu cầu đơn giản rồi kiểm tra luồng trả lời và thẻ xin quyền.

5
Thử Computer

Mở panel Computer, chọn môi trường cloud / Local VM hoặc This computer nếu muốn agent điều khiển máy Windows. Bắt đầu bằng một tác vụ không nhạy cảm và duyệt từng hành động.

Lưu ý Windows: Theo bảng trạng thái hiện tại của dự án, local bot control được hỗ trợ trên Windows x64, nhưng tính năng explicit preview-only local screen capture được ghi là unavailable. Đừng hiểu hai tính năng này là một.

6. Chạy từ source (Windows / macOS / Ubuntu)

Chỉ dùng cách này nếu muốn phát triển, sửa code hoặc chạy phiên bản từ repository. Yêu cầu Node 24+, pnpm và ít nhất một agent CLI đã đăng nhập.

PowerShell / Terminal

git clone https://github.com/milind-soni/OpenMausBot
cd OpenMausBot

pnpm install

Mở ba terminal riêng và giữ các tiến trình chạy:

# Terminal 1: harness server
pnpm dev:server

# Terminal 2: giao diện web dev
pnpm dev

# Terminal 3: Electron desktop
pnpm dev:desktop

Địa chỉ mặc định trong môi trường phát triển: giao diện http://127.0.0.1:5199, harness 127.0.0.1:8799.

Kiểm tra chất lượng / build:

pnpm typecheck
pnpm test
pnpm build
pnpm check:electron

Đóng gói trên Windows:

pnpm package:win

7. Ubuntu Desktop

Ubuntu 24.04 x64 có bản .deb và AppImage, nhưng trạng thái desktop được đánh dấu beta. GNOME là desktop được hỗ trợ. Tải từ Releases.

Cài gói .deb (khuyến nghị theo dự án)

sudo apt install ./OpenMausBot-amd64.deb

Chạy AppImage

chmod +x OpenMausBot.AppImage
./OpenMausBot.AppImage

Cài và đăng nhập các CLI agent dưới đúng user Linux sẽ chạy OpenMausBot. Local control trên Ubuntu chỉ beta và có khác biệt lớn giữa Xorg và Wayland: Xorg có opt-in; Wayland hiện bị khóa theo safety gate. Chat, cloud và Local VM vẫn có thể dùng.

8. Cài trên VPS / self-host

Có hai mô hình đáng phân biệt:

Mô hình A

Agent ở máy cá nhân, VPS làm máy tính từ xa

OpenMausBot và CLI agent ở Windows / máy cá nhân. VPS chỉ cung cấp remote desktop cho bot qua mô hình BYO VPS. Phù hợp khi muốn giữ Claude Code / Codex trên máy mình.

Mô hình B

Harness chạy trên VPS

Server chạy trên Ubuntu VPS; desktop app hoặc điện thoại pair vào server. Cần chuẩn bị đường truy cập an toàn và cài agent CLI ở đúng user chạy service nếu muốn agent chạy trên VPS.

8.1. Node CLI trên Ubuntu VPS

Yêu cầu Node 24+. Cài / đăng nhập agent CLI trước, sau đó chạy setup:

npx openmausbot setup

Chọn đúng một cách truy cập phù hợp. Ví dụ:

Điều kiệnLệnh
Đã có HTTPS reverse proxynpx openmausbot serve --public-url https://maus.example.com
Có domain và mở được 80/443npx openmausbot serve --domain maus.example.com
Dùng Tailscale trên server và thiết bịnpx openmausbot serve --tailscale
Chỉ truy cập trong LANnpx openmausbot serve --lan
Không có domain / tunnel sẵnnpx openmausbot login
npx openmausbot serve --tunnel

Khi server chạy, nó in pairing link/code. Trên desktop app chọn ＋ → Connect to a server, dán link. Pairing code dùng một lần và có thời hạn 10 phút; tạo code mới bằng npx openmausbot pair.

8.2. Docker Compose trên VPS có domain

Trên Ubuntu 22.04 / 24.04 x86-64 mới, tài liệu dự án có installer tự kiểm tra máy chủ và triển khai Docker + HTTPS:

# Chỉ kiểm tra điều kiện máy chủ, không thay đổi hệ thống
curl -fsSL https://raw.githubusercontent.com/milind-soni/OpenMausBot/main/deploy/install.sh | sudo sh -s -- --check

# Cài đặt (thay bằng domain của anh)
curl -fsSL https://raw.githubusercontent.com/milind-soni/OpenMausBot/main/deploy/install.sh | sudo sh -s -- --domain maus.example.com

# Lấy pairing link/code
cd /opt/openmausbot
sudo docker compose exec omb openmausbot pair

Installer ghi dữ liệu ở /opt/openmausbot; xem tài liệu Deploy on a VPS trước khi chạy để biết các kiểm tra, file được tạo và dịch vụ bên ngoài được liên hệ.

8.3. Docker Compose thủ công trong mạng riêng

git clone https://github.com/milind-soni/OpenMausBot
cd OpenMausBot

docker compose up -d --build
docker compose exec omb openmausbot pair

Mặc định tài liệu đưa ra địa chỉ localhost:8080. Nếu cho thiết bị khác trong LAN truy cập, phải cấu hình bind/public URL theo hướng dẫn Compose; không phơi HTTP thuần ra Internet.

Quan trọng cho VPS: Không tự mở port 8799 ra Internet. Harness mặc định nghe ở 127.0.0.1:8799; hãy dùng Tailscale, tunnel hoặc HTTPS reverse proxy đúng cấu hình. Pairing code không thay thế TLS hay firewall.

8.4. Chạy nền bằng systemd

# Cài service với cách truy cập phù hợp
npx openmausbot service install --tailscale

# Tạo pairing code khi cần
npx openmausbot pair

Lệnh service install tạo systemd unit trên Linux (hoặc launchd trên macOS) và in các lệnh sudo cần thiết. Dùng cùng user hệ điều hành cho setup và service; kiểm tra hướng dẫn self-hosting trước khi triển khai thật.

9. Kết nối Claude Code, Codex, Grok và engine riêng

OpenMausBot liệt kê các CLI agent được cài và đăng nhập trên máy. Các agent được nhắc trong README là Claude, Codex và Grok. Mỗi bot có thể chọn model phù hợp trong model picker, tùy provider và phiên bản CLI đang hoạt động.

  • Claude Code: cài CLI và đăng nhập bằng tài khoản / phương thức được Anthropic hỗ trợ.
  • Codex: cài CLI và xác thực theo tài liệu OpenAI.
  • Grok CLI: cài CLI tương ứng và xác thực theo tài liệu xAI.

README cũng nêu khả năng cấu hình custom CLI binary hoặc wrapper tại Settings → Engines. Tài liệu custom engines mô tả thêm việc tích hợp CLI hỗ trợ ACP hoặc endpoint tương thích OpenAI.

Liên quan 9Router / OmniRoute: Có thể nghiên cứu cấu hình custom engine / wrapper để chuyển request tới endpoint tương thích, nhưng không nên mặc định rằng chỉ nhập API URL là mọi tính năng CLI hoạt động. CLI agent có thể có cơ chế đăng nhập, tool protocol và quyền riêng. Cần kiểm tra tài liệu Custom Engines và thử nghiệm với một bot riêng trước.

11. Bảo mật — cần đọc trước khi cho Agent làm việc

  • Giữ harness ở loopback: mặc định server dùng 127.0.0.1:8799. Không port-forward trực tiếp cổng này ra Internet.
  • Dùng kênh truy cập có mã hóa: Tailscale, tunnel hoặc HTTPS reverse proxy. HTTP chỉ nên dùng trong mạng riêng được kiểm soát.
  • Pair từng thiết bị: pairing code dùng một lần, thời hạn ngắn. Không gửi code lên chat công khai hoặc lưu trong ảnh/video hướng dẫn.
  • Duyệt thao tác: kiểm tra lệnh shell, file edit, đăng nhập và thao tác gửi/xóa dữ liệu trước khi Allow.
  • Tách môi trường: ưu tiên cloud computer / Local VM cho tác vụ thử nghiệm; không cấp quyền vào thư mục chứa SSH key, token hoặc dữ liệu quan trọng nếu không cần.
  • Quản lý key: chỉ nhập key trong app chính thức, không commit vào Git, không đưa vào prompt hoặc ảnh chụp màn hình.
  • Cẩn trọng multi-user: tài liệu self-hosting có cảnh báo về loopback trust khi nhiều người dùng chung server. Cấu hình access control trước khi mở cho nhóm.
AI Agent có thể chạy lệnh và tương tác với ứng dụng. Chỉ cấp quyền tối thiểu cần thiết; không bật auto-approve toàn bộ trên máy có dữ liệu nhạy cảm.

13. Giới hạn và trạng thái cần lưu ý

  • Dự án tự mô tả là “early but real”: luồng message → agent → tool → approval → computer use đã chạy end-to-end, nhưng vẫn còn góc cạnh.
  • Ubuntu desktop đang beta; Wayland chưa cho bot điều khiển host do safety gate. Xorg có opt-in nhưng cũng beta.
  • Windows hỗ trợ local bot control, nhưng preview-only local screen capture được ghi là unavailable.
  • Cloud computer Boat và Composio là dịch vụ bên thứ ba; tài khoản, điều khoản và chi phí riêng.
  • Webhook receiver mặc định local; muốn nhận sự kiện từ Internet cần thiết kế relay/proxy riêng theo hướng dẫn, không mở toàn bộ API.
  • Không nên coi đây là nền tảng “AI tự chạy vô hạn không cần giám sát”. Approval, giới hạn quyền và kiểm tra kết quả vẫn rất quan trọng.

14. FAQ & tài liệu chính thức

OpenMausBot có miễn phí không?

Phần mềm lõi mã nguồn mở theo Apache 2.0 (ngoại lệ thư mục enterprise có điều khoản riêng). Model, subscription, cloud computer và tích hợp bên thứ ba có thể tốn phí.

Có cần Docker để cài Windows không?

Không nếu dùng installer desktop phát hành. Docker là một lựa chọn cho triển khai self-host server.

Có chạy trên VPS không có domain không?

Có thể dùng Tailscale hoặc tunnel theo tài liệu. Không nên dùng HTTP public trực tiếp. Docker installer một lệnh cho VPS yêu cầu domain trỏ tới server.

OpenMausBot có tự chứa Claude / GPT không?

Không. Đây là lớp điều phối Agent; anh phải cài / xác thực CLI hoặc cấu hình engine có quyền truy cập model.

Nên bắt đầu thế nào?

Cài desktop trên Windows, kết nối một CLI đã đăng nhập, tạo một bot thử nghiệm, sau đó mới thử computer use và integrations. Chỉ chuyển sang self-host VPS khi đã rõ nhu cầu truy cập từ xa.

Đề xuất triển khai: Với nhu cầu dùng Claude Code / Codex và làm việc trên Windows, bắt đầu bằng bản desktop Windows x64. Khi đã chạy ổn mới thử cấu hình custom engine (nếu muốn dùng endpoint riêng) và kết nối VPS qua Tailscale. Không cần đưa toàn bộ agent lên VPS ngay từ đầu.
