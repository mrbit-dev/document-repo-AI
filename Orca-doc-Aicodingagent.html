ORCA
AI Coding Agent Orchestrator

Cẩm nang tổng hợp khái niệm, kiến trúc, tính năng, cách cài đặt và cách vận hành Orca – môi trường desktop mã nguồn mở giúp tổ chức, quan sát và phối hợp song song nhiều AI Coding Agent trong cùng một luồng dự án.

Mã nguồn mở · MIT License Windows · macOS · Linux Multi-Agent Parallel Git Worktree cô lập SSH & Remote VPS
Định nghĩa trong một câu: Orca không phải là một AI model hay coding agent riêng rẽ. Đây là môi trường điều phối (Orchestration IDE) cho phép bạn chạy, theo dõi trực quan, review diff và điều phối nhiều CLI coding agent – như Claude Code, Codex, OpenCode, Cursor CLI – làm việc song song trên các Git Worktree hoàn toàn độc lập.

1. Orca là gì? Dùng để giải quyết vấn đề gì?

Trong quy trình phát triển hiện đại với AI, người lập trình thường xuyên mở hàng loạt cửa sổ terminal, tự gõ lệnh tạo branch, tự chuyển thư mục checkout, dò kết quả và so sánh thủ công. Khi chạy cùng lúc nhiều agent (như Claude Code và Codex), rủi ro xung đột ghi đè mã nguồn là rất lớn.

Orca được sinh ra với vai trò là một Agent Development Environment (ADE) – gom toàn bộ chu trình điều phối này vào một giao diện đồ họa thống nhất, hiện đại và bảo mật.

Orca LÀ

  • Desktop IDE / Workspace chuyên dụng cho AI coding agent.
  • Trình quản lý Git Worktree tự động tạo và dọn dẹp branch/thư mục.
  • Không gian tương tác: Review diff trực quan, comment ghi chú, tích hợp browser Chromium và editor.
  • Điều khiển đa môi trường: Chạy local trên laptop hoặc kết nối máy chủ Linux/VPS qua SSH.

Orca KHÔNG PHẢI

  • Không phải mô hình AI: Không tự sinh ra mã nguồn nếu thiếu agent CLI.
  • Không thay thế Claude Code / Codex: Các agent này vẫn là bộ máy thực thi lệnh.
  • Không bao gồm token/credits: Bạn vẫn tự quản lý API key hoặc gói tài khoản của mình.
  • Không bán hosting VPS: Mọi máy chủ từ xa đều do bạn tự kết nối và quản trị.

Kịch bản ví dụ thực tế

Giả sử bạn cần xây dựng tính năng “Xác thực người dùng & Phân quyền RBAC”. Thay vì làm lần lượt, bạn mở Orca và tạo cùng lúc 3 Git Worktree độc lập:

  • Worktree 1 (Claude Code): Triển khai API, middleware và JWT schema.
  • Worktree 2 (Codex): Viết unit tests, security audits và edge cases.
  • Worktree 3 (OpenCode): Dựng form đăng nhập giao diện Frontend.

Mỗi agent làm việc trên một thư mục riêng biệt. Bạn dễ dàng xem diff so sánh, comment yêu cầu sửa đổi, chọn phương án tối ưu nhất và merge về nhánh chính mà không sợ xung đột file.

Giá trị cốt lõi: Orca giải phóng lập trình viên khỏi công việc quản lý cửa sổ terminal và rủi ro ghi đè mã nguồn. Chất lượng phần mềm cuối cùng vẫn bắt nguồn từ năng lực prompt, model AI và quy trình review cẩn trọng của bạn.

2. Các khái niệm nền tảng cần nắm rõ

2.1. AI Coding Agent / CLI Agent

Là các chương trình AI thực thi thông qua giao diện dòng lệnh (Command Line Interface), có khả năng đọc/ghi file mã nguồn, chạy lệnh shell, kiểm thử và tương tác với Git. Orca đóng vai trò là host khởi chạy và quản lý vòng đời cho các CLI agent này.

2.2. Cơ chế Git Worktree

Git Worktree là tính năng cao cấp của Git cho phép một repository cục bộ có nhiều thư mục làm việc (working directories) hoạt động song song cùng lúc. Mỗi Worktree gắn liền với một branch riêng nhưng cùng chia sẻ thư mục lưu trữ Git nội bộ (.git). Nhờ đó, máy tính tiết kiệm dung lượng đĩa và không cần clone lại toàn bộ repo.

Cấu trúc Git Worktree đa Agent trong Orca
ai-shop/                 # Repository gốc (Checkout nhánh main)
├── ai-shop-auth/        # Worktree 1: Nhánh feature/auth (Claude Code đang làm)
├── ai-shop-review/      # Worktree 2: Nhánh review/auth (Codex đang phân tích)
└── ai-shop-frontend/    # Worktree 3: Nhánh feature/frontend (OpenCode dựng giao diện)

Trong Orca, vòng đời chuẩn của một tác vụ: Tạo Worktree mới → Khởi chạy Agent → Quan sát & Sửa code → Review Diff trực quan → Commit/Push/Tạo PR → Archive hoặc Xóa Worktree.

Base Ref

Nhánh tham chiếu nền tảng của repository, thường mặc định là origin/main hoặc develop.

Start-from Ref

Điểm xuất phát (commit hoặc nhánh cụ thể) mà Worktree mới được phân nhánh để bắt đầu triển khai nhiệm vụ.

2.4. Phân biệt Local, SSH và Remote Orca Server

Orca linh hoạt cung cấp nhiều môi trường thực thi: từ máy cá nhân (Local), kết nối qua giao thức Secure Shell (SSH Target), đến cụm máy chủ chuyên dụng (Remote Orca Server) hoặc các máy ảo Cloud VM cô lập theo workspace.

3. Khám phá 12 nhóm tính năng cốt lõi

Dưới đây là chi tiết toàn bộ các khối chức năng tạo nên sức mạnh điều phối của Orca:

3.1. Parallel Worktrees – Chạy đa agent song song

Đa nhiệm

Phân rã các tác vụ phức tạp thành nhiều Worktree độc lập. Bạn có thể giao cùng một bài toán khó cho 2 agent giải quyết theo 2 hướng tiếp cận khác nhau để chọn ra phương án code tối ưu nhất.

Lưu ý quan trọng: Dù cho nhiều agent chạy song song, tuyệt đối không tự động merge gộp máy móc mọi nhánh vào main. Bạn phải luôn là người kiểm duyệt (review) diff và chạy test suite.

3.2. Agent Management – Tương thích mọi CLI Agent

Hệ sinh thái

Orca hỗ trợ nguyên bản hoặc cắm thêm bất kỳ coding agent nào hoạt động được qua giao diện terminal. Danh mục chính thức tương thích bao gồm:

Claude Code Codex CLI OpenCode Cursor CLI GitHub Copilot Gemini CLI DeepSeek Harness Qwen Code Hermes Agent Kimi

3.3. Terminal Splits

Chia màn hình terminal ngang/dọc linh hoạt. Render tăng tốc phần cứng qua WebGL, tìm kiếm nội dung scrollback mượt mà và tự động phục hồi phiên làm việc sau khi khởi động lại ứng dụng.

3.4. Editor & Drag Files

Trình soạn thảo mã nguồn tích hợp với tính năng tự động lưu (autosave), tìm file nhanh và khả năng kéo thả trực tiếp file, ảnh chụp lỗi UI vào ô chat prompt của agent để cấp ngữ cảnh tức thì.

3.5. Browser tích hợp & Design Mode

UI Debugging

Mỗi Worktree có một tab trình duyệt Chromium riêng biệt để chạy trực tiếp ứng dụng web đang phát triển:

  • 1. Khởi chạy dev server (ví dụ: npm run dev) trong terminal của Worktree.
  • 2. Mở trình duyệt nội bộ truy cập http://localhost:3000.
  • 3. Bật Design Mode: Click chọn bất kỳ element nào trên trang web.
  • 4. Orca sẽ tự động trích xuất mã HTML/CSS thực tế kèm ảnh crop element để đính kèm vào prompt gửi cho Agent yêu cầu sửa chữa.

3.6. Annotate AI Diffs

Cho phép chọn từng dòng mã nguồn bị thay đổi trong cửa sổ Review Diff, gõ nhận xét định dạng Markdown và bấm gửi trả ngược lại cho agent để nó tự động sửa tiếp.

3.7. GitHub & Linear

Duyệt danh sách Pull Requests, Issues và bảng Linear ngay trong ứng dụng. Click mở một task sẽ tự động sinh Worktree gắn liền với ngữ cảnh của issue đó.

3.8. SSH Worktrees – Khai thác sức mạnh VPS từ xa

Cloud Runtime

Toàn bộ mã nguồn, tác vụ build nặng và CLI agent được thực thi trên máy chủ Linux/VPS từ xa thông qua SSH. Giao diện người dùng, trình soạn thảo, màn hình diff và phím tắt vẫn mượt mà trên máy laptop cá nhân của bạn. Tự động phục hồi kết nối (auto-reconnect) và tự động chuyển tiếp cổng (port forwarding).

3.9. Remote Server & Cloud VM

Tự lưu trữ runtime tập trung phục vụ nhiều máy trạm hoặc tự động hóa hạ tầng qua Cloud VM theo từng workspace độc lập.

3.10. Mobile Companion

Ứng dụng đồng hành trên iOS/Android ghép cặp với máy tính để nhận thông báo hoàn tất task và gửi tin nhắn prompt theo dõi ngay trên smartphone.

3.11. Orca CLI & Agent Skills

Cho phép script hoặc agent bên ngoài gửi lệnh điều khiển ngược lại cửa sổ Orca (tạo Worktree, đổi branch, thao tác UI).

3.12. Quick Open & Trực quan

Hộp lệnh Cmd/Ctrl+K tìm kiếm tức thì Worktree, file, lệnh và xem trước trực tiếp file Markdown, ảnh hình ảnh, tài liệu PDF nội bộ.

4. Quy trình vận hành chuẩn từ đầu đến cuối

Để đạt hiệu suất tối ưu và tránh rủi ro lỗi mã nguồn, hãy tuân thủ chu trình 10 bước dưới đây:

1
Khởi động ứng dụng Orca
Mở ứng dụng desktop tương ứng với hệ điều hành của bạn. Lần đầu mở, Orca sẽ xin quyền truy cập thư mục làm việc và đề nghị import cấu hình CLI hiện có.
2
Chuẩn bị Git Repository sạch
Đảm bảo dự án đã được quản lý bằng Git. Hãy commit hoặc git stash toàn bộ các file dang dở trước khi phân nhánh Worktree.
3
Thêm Repo (Add Repo)
Chọn Add Repo trên giao diện Orca để trỏ đến thư mục dự án local hoặc chọn repository trên máy chủ SSH từ xa.
4
Tạo Worktree theo tác vụ (Create Worktree)
Đặt tên Worktree ngắn gọn, chuẩn hóa theo task (ví dụ: feature-auth-api). Chọn điểm xuất phát (start-from ref) từ nhánh main hoặc branch mong muốn.
5
Chọn AI Coding Agent
Khởi tạo terminal với CLI agent đã cài đặt và đăng nhập sẵn (Claude Code, Codex, OpenCode...). Hoặc mở Blank Terminal nếu muốn chạy shell thủ công.
6
Giao nhiệm vụ (Prompting)
Viết prompt nêu rõ: mục tiêu cốt lõi, phạm vi file được phép sửa, các ràng buộc kỹ thuật, tiêu chí nghiệm thu và lệnh chạy test tự động.
7
Quan sát & Điều phối
Theo dõi luồng chạy qua terminal split. Kéo thả thêm file ngữ cảnh hoặc dùng Design Mode trên trình duyệt để phản hồi kịp thời khi agent bị chệch hướng.
8
Kiểm tra Diff kỹ lưỡng (Review Diff)
Đọc từng dòng thay đổi (line-by-line). Thêm nhận xét (inline comment) trên diff để yêu cầu agent chỉnh sửa các chi tiết chưa chuẩn.
9
Chạy kiểm thử & Commit / Pull Request
Chạy npm test hoặc test suite của dự án. Sau khi mọi kiểm tra xanh lá, thực hiện commit trên branch của Worktree và mở Pull Request.
10
Dọn dẹp Worktree (Archive / Delete)
Khi PR đã được merge vào main, lưu trữ (archive) hoặc xóa Worktree để giải phóng dung lượng đĩa cho máy tính.
Quy tắc vàng: AI Agent báo “Nhiệm vụ đã hoàn tất” chưa bao giờ đồng nghĩa với việc mã nguồn đã hoàn toàn chính xác. Bạn – người kỹ sư phần mềm – luôn phải giữ vai trò gatekeeper: đọc diff, rà soát logic bảo mật và chạy test suite trước khi merge.

5. Hướng dẫn cài đặt trên Windows 10 / 11

Đối với môi trường Windows sử dụng PowerShell, đây là quy trình cài đặt nhanh chóng và chuẩn xác nhất:

5.1. Tải và cài đặt Orca Desktop

Bản cài đặt chính thức cho Windows (.exe)
Hỗ trợ Windows 10 & 11 (64-bit) · Tự động kiểm tra cập nhật mới
Tải orca-windows-setup.exe

Sau khi tải, mở file cài đặt và làm theo hướng dẫn trên màn hình. Nếu ứng dụng hiển thị popup xin cấp quyền truy cập thư mục home để tìm kiếm repository, hãy chọn đồng ý.

5.2. Kiểm tra các công cụ lập trình cần thiết

Mở PowerShell và kiểm tra các công cụ runtime cùng các CLI agent bạn dự định sử dụng:

Kiểm tra phiên bản công cụ trong PowerShell
# Kiểm tra môi trường nền tảng
node -v
npm -v
git --version

# Kiểm tra các CLI Agent (chỉ cần cài những agent bạn sở hữu tài khoản)
claude --version
codex --version
opencode --version

5.3. Chuẩn bị dự án Git trên máy tính

Kiểm tra trạng thái Git cục bộ
# Di chuyển vào thư mục dự án (Ví dụ trong Laragon)
cd E:\laragon\www\ai-shop

# Kiểm tra trạng thái Git
git status
git branch --show-current
git remote -v
Trước khi khởi tạo Git Worktree: Hãy kiểm tra file .gitignore để loại trừ ngay: .env, private keys, thư mục node_modules, build caches và file dữ liệu bí mật. Tuyệt đối không commit credential vào Git.

6. Cài đặt trên Linux và macOS

Hệ điều hành Linux

Tải AppImage, gói .deb hoặc .rpm từ bản phát hành mới nhất.

# Tải AppImage chính thức
wget -O Orca.AppImage \
  https://github.com/stablyai/orca/releases/latest/download/orca-linux.AppImage

chmod +x Orca.AppImage
./Orca.AppImage

Lưu ý: Trên Linux, file binary CLI được đặt tên là orca-ide để tránh trùng với trình đọc màn hình mặc định của GNOME Orca.

Hệ điều hành macOS

Tải bộ cài đặt cho chip Apple Silicon (M1/M2/M3/M4) hoặc dùng Homebrew với tên định danh đầy đủ:

# Cài đặt qua Homebrew Cask chuẩn
brew install --cask stablyai/orca/orca

# Nâng cấp khi có bản mới
brew upgrade --cask stablyai/orca/orca
Cảnh báo: Không gõ brew install --cask orca vì sẽ bị nhầm sang gói phần mềm đồ thị của Plotly!

7.1. Cấu hình SSH Target trong Orca

  1. A
    Mở mục Cấu hình SSH
    Trên cửa sổ Orca, điều hướng đến Settings → SSH → Add Target.
  2. B
    Điền thông số kết nối
    Nhập Host IP, username, port (mặc định 22) và đường dẫn đến file SSH Private Key (hoặc chọn sẵn host từ ~/.ssh/config). Bấm Test Connection.
  3. C
    Mở Worktree trên máy chủ VPS
    Mở thư mục dự án trên VPS, khi tạo Worktree mới chọn mục Run on: [Tên SSH Host]. Khi máy laptop gập màn hình hoặc đứt mạng, agent trên VPS vẫn tiếp tục chạy độc lập.

7.2. Danh sách kiểm tra SSH (Checklist tương tác)

Click để đánh dấu các bước chuẩn bị an toàn cho máy chủ VPS của bạn:

  • VPS đã cài đặt sẵn Git, Node.js, Python và các CLI Agent cần thiết.
  • User SSH có toàn quyền đọc/ghi trên thư mục dự án và có quyền tạo thư mục Worktree.
  • Xác thực bằng SSH Key bảo mật (Ed25519/RSA), tắt tính năng đăng nhập bằng password của user root.
  • Đã kiểm tra dung lượng ổ đĩa (df -h) và RAM của VPS đủ cho nhiều agent song song.
  • File biến môi trường nhạy cảm .env được bảo vệ riêng trên VPS, không lộ vào prompt.

7.3. So sánh các chế độ triển khai

Chế độ triển khai Môi trường thực thi Phù hợp nhất với
Local Worktree Máy tính cá nhân hiện tại Phát triển hàng ngày, setup đơn giản, không cần mạng internet ổn định.
SSH Worktree Ubuntu VPS / Máy chủ Dev riêng Tác vụ nặng, máy chủ luôn bật 24/7, laptop cấu hình vừa phải.
Remote Orca Server Server chạy Orca Runtime Đội ngũ chia sẻ tài nguyên tính toán tập trung, tích hợp CI/CD tự động.
Cloud Workspace VM Máy ảo theo từng workspace Môi trường dùng một lần (ephemeral), cô lập tuyệt đối mã nguồn theo từng task.

8. Orca CLI, Skills và Tự động hóa

Orca tích hợp sẵn CLI cho phép các script bên ngoài hoặc chính các AI Agent khác có thể tương tác và điều khiển một cửa sổ Orca đang chạy.

8.1. Cài đặt Skill chính thức cho AI Agent

Để agent của bạn tự biết cách gọi các tính năng của Orca, hãy cài đặt gói skill chính thức:

Cài đặt Orca Skill cho Agent
# Cách 1: Cài đặt thông qua npx skills
npx skills add https://github.com/stablyai/orca --skill orca-cli

# Cách 2: Nếu trong môi trường headless đã có orca CLI
orca skills install --skill orca-cli

8.2. Danh mục lệnh CLI thông dụng

Một số câu lệnh Orca CLI tiêu biểu
# 1. Xem hướng dẫn tổng quát
orca --help

# 2. Liệt kê toàn bộ Worktree đang hoạt động
orca worktree ps --json

# 3. Tạo nhanh một Worktree mới gắn với Repo
orca worktree create --repo id:<repoId> --name feature-payment --json

# 4. Gửi một chỉ thị prompt vào terminal đang mở
orca terminal send --text "Chạy test suite và tóm tắt lỗi nếu có" --enter --json

Trước khi thực hiện thay đổi, hãy đọc kỹ cấu trúc thư mục, quy ước code và tài liệu dự án.

Nhiệm vụ:
Triển khai module Authentication theo đúng phạm vi được giao.

Ràng buộc & Nguyên tắc bắt buộc:
1. Tuân thủ nghiêm ngặt coding standards hiện tại của dự án.
2. Không tự ý chỉnh sửa các file/thư mục nằm ngoài phạm vi được chỉ định.
3. Tuyệt đối không hardcode API keys, secrets hoặc thông tin nhạy cảm vào code.
4. Bắt buộc viết automated tests đầy đủ cho mọi hàm logic mới.
5. Chạy linter, formatter và test suite kiểm tra trước khi hoàn thành.
6. Tuyệt đối không tự ý chạy migration trên database môi trường production.

Tiêu chí nghiệm thu (Definition of Done):
- Mọi automated test liên quan đều vượt qua (100% pass).
- Không để lại các ghi chú TODO chưa xử lý.
- Tóm tắt danh sách file đã thay đổi, các quyết định kiến trúc và rủi ro tiềm ẩn.
- Không tự ý commit nếu chưa có sự xác nhận của người lập trình.
Những việc tuyệt đối KHÔNG cho các agent làm song song:
  • Nhiều agent cùng lúc can thiệp vào một file Migration hoặc Schema cơ sở dữ liệu.
  • Nhiều agent cùng chạy lệnh seed / reset database dùng chung.
  • Nhiều agent cùng deploy mã nguồn lên cùng một môi trường staging.
  • Cấp quyền cho agent xóa file bừa bãi mà không cần người dùng xác nhận.

10. Bảo mật, Quyền riêng tư & Vận hành

10.1. Bảo vệ Repository và Thông tin xác thực

  • Đưa các file chứa secret (.env, private keys, database config) vào file .gitignore.
  • Sử dụng SSH key chuyên dụng với quyền giới hạn, không cho phép agent thực thi với quyền root.
  • Mỗi tính năng hoặc mỗi thử nghiệm đều tạo Worktree riêng, không can thiệp trực tiếp nhánh main.
  • Luôn rà soát kỹ Review Diff trước khi thực hiện commit, push hoặc tạo Pull Request.
  • Tuyệt đối không đưa dữ liệu khách hàng hoặc thông tin thẻ vào khung chat prompt.

10.2. Lưu ý về file bị Ignore trong Git Worktree

Khi một Worktree mới được tạo ra, Git chỉ sao chép các file được commit và theo dõi. Các thư mục bị ignore như node_modules/ hoặc .env sẽ không tự động xuất hiện. Bạn cần chạy lệnh cài đặt dependency (ví dụ: npm install) hoặc sử dụng tính năng symlink chia sẻ theo tài liệu hướng dẫn của dự án.

10.3. Quyền riêng tư & Telemetry

Orca cam kết minh bạch về dữ liệu thu thập. Bạn có thể dễ dàng tắt hoàn toàn tính năng gửi dữ liệu ẩn danh (telemetry) trong mục Settings → Privacy bất cứ lúc nào.

11. Điểm mạnh, Hạn chế & Vị thế công nghệ

Điểm mạnh vượt trội

  • Điều phối nhiều agent song song bằng Git Worktree thật, không sợ đè code.
  • Trực quan hóa diff với tính năng comment phản hồi ngược cho AI ngay trong app.
  • Trình duyệt tích hợp với Design Mode trích xuất HTML/CSS và ảnh element tức thì.
  • Hỗ trợ SSH Worktrees mượt mà, biến laptop cá nhân thành bàn điều khiển VPS.
  • Mã nguồn mở chuẩn MIT, không khóa chặt (vendor lock-in) vào một hãng AI nào.

Chi phí & Hạn chế cần tính

  • Không tự cấp sẵn mô hình AI; người dùng tự chi trả API token/credit cho nhà cung cấp.
  • Mỗi Worktree nhân bản thư mục làm việc, làm tăng dung lượng ổ cứng của máy.
  • Chạy quá nhiều agent cùng lúc có thể gây quá tải RAM và ngốn dung lượng token nhanh.
  • Giải quyết xung đột merge (merge conflict) vẫn đòi hỏi kinh nghiệm chuyên môn của kỹ sư.

12. Câu hỏi thường gặp (FAQ)

1. Orca có thực sự miễn phí không?
Hoàn toàn miễn phí. Orca là phần mềm mã nguồn mở phát hành theo giấy phép MIT. Bạn có thể sử dụng cho cá nhân hoặc doanh nghiệp mà không phải trả phí bản quyền cho phần mềm Orca. Tuy nhiên, chi phí subscription hoặc API token của các nhà cung cấp như Claude, OpenAI Codex hay VPS vẫn do bạn tự chi trả.
2. Tôi có bắt buộc phải cài đặt Node.js để chạy Orca Desktop không?
Không bắt buộc với bản thân ứng dụng Orca vì nó là một desktop app đóng gói độc lập. Tuy nhiên, nếu CLI agent của bạn (như Claude Code hoặc các tool dev web) yêu cầu môi trường Node.js để chạy thì bạn cần cài Node.js trên máy tương ứng.
3. Tôi có thể dùng Orca nếu không có tài khoản Claude Code không?
Có! Orca không khóa bạn vào bất kỳ agent nào. Bạn hoàn toàn có thể dùng Codex, OpenCode, Cursor CLI, Qwen Code hoặc thậm chí chỉ dùng Orca như một trình quản lý đa terminal và Git Worktree cực kỳ tiện lợi cho công việc hàng ngày.
4. Khi tôi đóng laptop, agent trên VPS có tiếp tục chạy không?
Có! Khi kết nối qua SSH Worktrees, tiến trình agent chạy trực tiếp trên hệ điều hành của VPS từ xa. Khi bạn đóng máy tính hoặc ngắt kết nối mạng, tiến trình vẫn tiếp tục thực hiện. Khi bạn mở lại Orca, phần mềm sẽ tự động kết nối lại (auto-reconnect) và hiển thị tiếp output của terminal.
5. Các agent làm việc song song có thể ghi đè làm mất mã nguồn của nhau không?
Không! Mỗi agent được cấp một Git Worktree hoàn toàn riêng biệt với thư mục làm việc vật lý và branch độc lập. Chúng không bao giờ ghi đè trực tiếp lên nhau. Bạn là người kiểm tra diff và quyết định merge thay đổi nào vào nhánh chính.
6. Orca có thay thế hoàn toàn GitHub hay GitLab không?
Không. Orca chỉ tích hợp giao diện duyệt nhanh Pull Request và Issue để bạn tiện thao tác. Mã nguồn, quyền kiểm soát truy cập và hệ thống CI/CD vẫn thuộc về nhà cung cấp Git Remote của bạn.
7. Làm thế nào để giải phóng dung lượng ổ cứng sau khi hoàn thành task?
Sau khi branch của bạn đã được merge vào main, bạn chỉ cần click chuột phải vào Worktree trong Orca và chọn Archive hoặc Delete Worktree. Orca sẽ tự động chạy lệnh dọn dẹp thư mục con an toàn mà không làm ảnh hưởng đến lịch sử Git.
